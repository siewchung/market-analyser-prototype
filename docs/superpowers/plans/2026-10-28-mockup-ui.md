# Mockup UI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Rebuild the UI as the three-screen dashboard in the mockup (Overview, Quality, Analytics), with data loaded at startup, on the existing browser-only architecture.

**Architecture:** No backend. At startup the worker fetches the 40 committed daily Parquet files (1.1 MB) and reads a committed, precomputed quality report covering the full dataset, daily and minute. Minute data (100 MB, downloaded, gitignored) is fetched one contract at a time when Analytics needs it. File URLs come from `import.meta.glob(..., { query: '?url' })` inside the worker, so there's no hand-written manifest. Uploading a file replaces the active data with a live analysis of that file. Reset goes back to the startup data.

**Tech Stack:** TypeScript (strict), Vite 8, React 19, Recharts 3, hyparquet, Vitest. No new dependencies.

**Spec:** `docs/Futures DQ Dashboard Mockup.pdf` (layout and copy), plus the decisions recorded in this conversation on 2026-10-28. `docs/HANDOFF.md` is **not** the spec. Its Fastify and backend design was rejected. Only its mockup corrections 2 to 5 (section 11) still apply.

## Why the data is served this way (measured 2026-10-28, Node, one run each)

| Load | Rows | Time | Peak heap |
|---|---|---|---|
| All 40 daily files | 30,102 | 0.3 s | 41 MB |
| All 40 minute files | 5,295,239 | 76 s | 3.9 GB |
| Largest minute file (SR3M26) | 679,428 | 4.5 s | 520 MB |

Loading all minute data in a browser tab is not viable. Daily data at startup plus minute data per contract is. The quality report for minute data is therefore computed offline by a script, one file at a time.

## Global Constraints

- Timestamps are Chicago wall-clock stored as if UTC. Read them only with `getUTC*`.
- Trading date = CME session date (17:00 CT onward counts as the next day). Never use the dataset's `trading_date` column.
- `src/domain` stays pure: no DOM, no fetch, no I/O.
- No new runtime or dev dependencies. No router library and no state library. Tabs use the URL hash.
- Named exports only. Explicit types on exported functions. `readonly` on data shapes.
- Comments must be readable by a junior developer or a business user, matching the existing style.
- Light theme only, matching the mockup. Colours are CSS custom properties on `:root`.
- Touch targets are at least 44 px. Use real `button`, `label` and `table` elements.
- Up and down candles differ by fill (hollow up, solid down), not only by colour.
- Layout works at 390 px wide with no horizontal page scroll (wide tables scroll inside their card).
- Mockup corrections that apply: header shows real counts; the issue-log timestamp column shows date only for daily data; no "Mock data" tag; all mockup numbers are illustrative.
- Done means `npm run typecheck` and `npm test` pass, plus a manual check of all three tabs at 1280 px and 390 px.

## Decisions this plan makes (flagged for review)

1. **Health percentage** = clean rows ÷ records read, labelled "of records usable for analytics". The mockup's "of records accepted" would always read 100% on the real sample, which has zero rejected rows.
2. **Issue labels** use the existing `ISSUE_LABELS`, not the mockup's wording.
3. **"Exclude bars with errors"** defaults to on (the current behaviour). Off keeps bars with impossible prices and the later copy of conflicting duplicates. Exact duplicates are still dropped and negative volume is still blanked.
4. **Daily bars and candles in Analytics** come from the contract's minute data when it's downloaded, so the session rule gives 1,380 bars a day like the mockup. Otherwise they come from the daily file, with a note saying so.
5. **The issue log** shows a sample: up to 200 issues per severity, with a "showing X of Y" line. The full minute log is 346k issues and can't be shipped.
6. **The quality report JSON is committed** (`data/quality-report.json`), so a fresh clone gets the full report without downloading 100 MB. A version constant guards against drift.
7. **Built-in sample buttons are removed.** The README tells reviewers to upload `tests/fixtures/dirty.csv` to see planted defects.

## Review Focus

1. **Fresh clone with no `sample-data/`.** Startup must still work, and Analytics falls back to daily data with a "minute data not downloaded" note. Pinned in Task 4 (`buildStartupSources` with no minute URLs).
2. **Fast contract switching while a minute file is loading.** The chart must never show the contract the user left. Pinned in Task 4 (serial queue test). The hook also drops stale `queryId`s (Task 5).
3. **Uploading a single-contract CSV that includes rejected rows.** The Quality screen must show a live report for that file, not the startup one. Pinned in Task 2 (report from `dirty.csv`).
4. **Committed report out of date with the code.** Pinned in Task 3 (version test).
5. **A daily-only contract in Analytics.** The VWAP chart shows an explanation instead of an empty plot, and the VWAP day picker is disabled. Pinned in Task 6 (`query` on daily data returns `barInterval: 'daily'`) plus the manual check in Task 10.

### Task 2: Quality report builder

**Files:**
- Create: `src/application/qualityReport.ts`
- Test: `tests/unit/application/qualityReport.test.ts`

**Interfaces:**
- Consumes: `Dataset` and `load` from `analyse.ts`; `fileInterval`, `rootOf` (Task 1); `generateInsights`; `SEVERITY`.
- Produces:

```ts
export const QUALITY_REPORT_VERSION = 1;
export const ISSUE_SAMPLE_PER_SEVERITY = 200;
export const REJECTED_SAMPLE_SIZE = 200;

/** What one analysed file contributes to a report. Holds no bars, so many files fit in memory. */
export interface FileAnalysis {
  readonly fileName: string;
  readonly interval: BarInterval;
  readonly summary: LoadSummary;
  readonly issues: readonly QualityIssue[];
  readonly rejected: readonly RejectedRow[];
}
export interface ReportIssue { readonly issue: QualityIssue; readonly interval: BarInterval }
export interface ReportRejected { readonly fileName: string; readonly row: RejectedRow }
export interface ReportContract {
  readonly contract: string; readonly root: string;
  readonly intervals: readonly BarInterval[]; // sorted: 'intraday' before 'daily'
  readonly firstDate: string; readonly lastDate: string;
  readonly bars: number; readonly errors: number; readonly warnings: number; readonly info: number;
}
export interface QualityReport {
  readonly version: number;
  readonly files: Readonly<Record<BarInterval, number>>;
  readonly totalRows: number; readonly acceptedRows: number;
  readonly rejectedRows: number; readonly cleanRows: number;
  readonly dateRange: { readonly from: string; readonly to: string } | null;
  readonly roots: readonly string[];
  readonly issueCounts: Readonly<Record<IssueKind, number>>;
  readonly severityCounts: Readonly<Record<Severity, number>>;
  readonly contracts: readonly ReportContract[]; // sorted by contract
  readonly insights: readonly Insight[];
  readonly issueSample: readonly ReportIssue[]; // ≤ ISSUE_SAMPLE_PER_SEVERITY per severity, most serious first, then by time
  readonly rejectedSample: readonly ReportRejected[];
}
export function toFileAnalysis(fileName: string, dataset: Dataset): FileAnalysis;
export function buildQualityReport(files: readonly FileAnalysis[], config: AnalysisConfig): QualityReport;
```

`buildQualityReport` merges contracts that appear in several files: sum counts, take the min first date and max last date, and union the intervals. It runs `generateInsights` once over all files' issues and rejects, with `barsPerContract` summed across files.

### Task 5: Worker protocol, worker and hook

**Files:**
- Modify: `src/infrastructure/worker/protocol.ts`, `src/infrastructure/worker/analysis.worker.ts`, `src/ui/useAnalysis.ts`

**Interfaces:**
- Produces:

```ts
export type DataOrigin = 'startup' | 'uploaded';
export type WorkerRequest =
  | { readonly type: 'startup' } // also used for Reset
  | { readonly type: 'load'; readonly fileName: string; readonly bytes: ArrayBuffer }
  | { readonly type: 'query'; readonly queryId: number; readonly filter: Filter; readonly view: ViewOptions };
export type WorkerResponse =
  | { readonly type: 'ready'; readonly origin: DataOrigin; readonly fileName: string | null;
      readonly report: QualityReport; readonly minuteContracts: readonly string[] }
  | { readonly type: 'result'; readonly queryId: number; readonly result: QueryResult }
  | { readonly type: 'error'; readonly message: string };

// useAnalysis
export type AnalysisState =
  | { readonly status: 'loading'; readonly message: string }
  | { readonly status: 'error'; readonly message: string }
  | { readonly status: 'ready'; readonly origin: DataOrigin; readonly fileName: string | null;
      readonly loadedAt: Date; readonly report: QualityReport; readonly minuteContracts: readonly string[];
      readonly filter: Filter; readonly view: ViewOptions;
      readonly result: QueryResult | null; readonly pending: boolean };
export function useAnalysis(): { state: AnalysisState; uploadFile(fileName: string, bytes: ArrayBuffer): void;
  reset(): void; setFilter(filter: Filter): void; setView(view: ViewOptions): void };
```

Worker behaviour, with every request run through `createSerialQueue`:
- `startup`: fetch all daily URLs in parallel, parse them, concatenate records, `load('daily sample', …)`. The report is the imported `data/quality-report.json`. Throw if its version doesn't match `QUALITY_REPORT_VERSION`. Clear the minute cache.
- `load`: `load(fileName, …)`. Report = `buildQualityReport([toFileAnalysis(fileName, dataset)], DEFAULT_CONFIG)`. `minuteContracts = []`.
- `query`, origin startup: if the filter's contract has minute data, use a one-entry cache `{ contract, dataset }`, replacing it when the contract changes. Otherwise use the daily dataset. Origin uploaded: use the uploaded dataset.

The hook sends `startup` on mount. It sets `pending: true` on each query and ignores `result` messages whose `queryId` isn't the latest. The first query after `ready` uses `{ contracts: [report.contracts[0].contract], excludeErrors: true }`.
